# Политики безопасности FINANSES

## Аутентификация и роли
- Пользователи: `admin`, `user`, `viewer`.
- Пароли хранятся с `password_hash()` (bcrypt).
- Первичный администратор: логин `admin`, пароль `admin123`, флаг `must_change_password=1`.
- После сброса пароля пользователь обязан сменить его при первом входе.

## Сессии
- Сессия стартует в `Helpers::startSession()` со следующими флагами:
  - `httponly = true`, `samesite = Lax`, `secure` при HTTPS.
  - `SESSION_LIFETIME` задаётся в `.env` (по умолчанию 1800 секунд).
- Для REST API предусмотрен флаг `USE_JWT` (зарезервировано для будущего расширения).

## CSRF
- Токен генерируется `Helpers::csrfToken()` и хранится в сессии.
- Все mutating запросы (`POST/PUT/PATCH/DELETE`) проверяют `X-CSRF-TOKEN` или поле `csrf_token`.
- При несоответствии возвращается HTTP 419.

## Валидация и XSS
- `Helpers::sanitize()` используется при выводе пользовательских строк.
- На фронте применяются `textContent`/`innerText` при вставке данных.
- Файлы фильтруются по MIME и размеру (`MAX_UPLOAD_SIZE`). Запрещены `.php` и исполняемые расширения.

## Хранение файлов
- Директория `storage/` недоступна напрямую из веба (см. `.htaccess` и `nginx.conf`).
- Файлы выдаются через `FileController`, проверяется доступ по роли/автору.
- PDF генерируются в `storage/pdf`, повторные запросы возвращают кешированный файл.

## Аудит и логирование
- Таблица `audit_log` хранит события `login`, `logout`, `create_request`, `update_status`, `generate_pdf`, `upload_file`, `export_report`, etc.
- Локальный лог `storage/logs/app.log` содержит служебные сообщения (`Helpers::log`). Настройте ротацию (`logrotate`).

## Политика паролей
- Минимальная длина задаётся в `.env` (`PASSWORD_POLICY_MIN_LENGTH`, default 8).
- Рекомендуется включить дополнительные правила (цифры, спецсимволы) на уровне UI/валидации.

## Ограничение скорости
- Базовый rate limit на /api/auth.php?action=login рекомендовано реализовать на уровне веб-сервера (Apache mod_ratelimit или fail2ban). В коде предусмотрены хуки для расширения.

## Обновления и патчи
- Перед обновлением делайте бэкап БД и `storage/`.
- Используйте `composer update` с осторожностью, проверяйте изменение major-версий.
- Периодически проверяйте уязвимости зависимостей (`composer audit`).

## Политика ролей
- `admin`: полный доступ (заявки, пользователи, отчёты, журнал).
- `user`: свои заявки и файлы, просмотр материалов, создание запросов.
- `viewer`: чтение заявок и отчетов без изменения (реализуйте через дополнительные проверки в `RequestController`).

## Дополнительные меры
- Разрешите доступ к админ-панели только из корпоративной сети (настройки веб-сервера).
- Включите HTTPS с доверенным сертификатом.
- Настройте резервное копирование MySQL (ежедневно) и файлов (еженедельно).
- Логи аудита храните минимум 1 год.
